# Мобильное приложение для ведения совместного учёта семейных дел

## 1 Анализ предметной области

Предложение предназначено для групп пользователей, ведущий совместный учёт дел. Система позволяет создавать, хранить, удалять и изменять задачи, а также синхронизирует статус этих задач между всеми пользователями в одной семье. Приложение также имеет возможность вносить данные о питомцах.

**Типы пользователей:** владелец семьи, взрослый, ребёнок, работник (няня)

**Внешние системы:** push-сервисы, почтовый сервис для приглашения в семью, синхронизация с календарем.

### Пользовательские сценарии

1. Как владелец семьи, я хочу добавлять пользователей в семью и контролировать их роли, чтобы каждый видел и мог делать в приложении только то, что соответствует его роли.
2. Как взрослый я хочу создавать, назначать исполнителя и срок, чтобы домашние дела были распределены прозрачно и ничего не терялось.
3. Как взрослый я хочу изменять и удалять задачи, чтобы список задач оставался всегда актуальным.
4. Как ребёнок, я хочу видеть свои задачи и отмечать их выполненными, чтобы знать, что от меня ожидается и родители были в курсе результата.
5. Как участник семьи, я хочу, чтобы статус задачи обновлялся у всех после его изменения, чтобы не дублировать дела.
6. Как работник (няня), я хочу видеть задачи, назначенные мне или относящиеся к опекаемому, не получая доступа к лишним данным.

### Доменные события

ЗадачаСоздана, ИсполнительНазначен, ЗадачаВыполнена, ЗадачаУдалена, ЗадачаВыполнена, ЧленСемьиДобавлен, ЧленСемьиУдален, РольНазначена.

### Группировка

#### Роли

- **Владелец семьи** – создатель семьи, имеет право добавлять и удалять участников.
- **Взрослый** – участник семьи, имеет право создавать, назначать задачи ребёнку и работнику и брать доступные задачи.
- **Ребёнок** – участник семьи, имеет право менять статус задач и брать доступные задачи.
- **Работник** – участник семьи, имеет право менять статус назначенных ему задач.

#### Календарь дел

- **Задача** – дело, которые необходимо выполнить и имеющее срок и статус.
- **Исполнитель** – участник семьи, назначенный для выполнения задачи.
- **Статус** – состояние, в которых может находться задача.
- **Срок** – дата, до которого необхожимо выполнить задачу.

## 2 Список и описание сервисов

| Сервис | Ответственность | Владеет данными | Почему отдельный |
|---|---|---|---|
| family-service | состав семьи, приглашения, роли, права доступа | семья, участник, рола, права | «участник» и «роль» здесь означают права, а не исполнителя. Модель прав меняется независимо от задач, |
| task-service | CRUD задач, назначение исполнителя, срока и статуса | Задача | CRUD задач, назначение исполнителя, срока и статуса. Единственный источник истины по статусу задачи. |
| pet-service | работа с карточкой пиотомца (кличка, порода и тд) | Питомец | У питомца собственные данные и жизненный цикл, в задачах он только объект привязки. Набор полей карточки будет расти независимо. Отдельные правила доступа для няни |
| sync-service | Доставляет изменения на устройства участников семьи в реальном времени | - | Не имеет собственных данных, могут понадобиться данные из нескольких сервисов |
| notification-service | Отправляет push- и email-уведомления | ЖурналОтправок | не влияет на основной сценарий, его сбой не должен ломать создание задачи, приглашение в семью и тд |

Авторизацию выполняет Keycloak, поэтому собственный сервис пользователей не пишется.

### Выбор готового ПО

| Компонент | Кто использует | Обоснование |
|---|---|---|
| PostgreSQL (отдельная база на сервис) | family, task, pet сервисы | транзакции и связи между сущностями |
| Redis | task-service | кеш задач |
| MongoDB | notification-service | журнал отправок с разной структурой для разных типов уведомлений/писем |
| RabbitMQ | family, task, pet, notification | сообщения между сервисами, очереди |
| Nginx | вход для клиента | маршрутизация, проверка JWT, ограничение частоты запросов |
| Keycloak | Gateway | OAuth 2.0 / OpenID Connect |
| MiniO | family, pet сервисы | Хранение аватарок, картинок. Более автономна в отличие от S3 |

| 6 | клиент → task | sync | `POST /api/v1/tasks` | создать задачу |

| 10 | task → sync | async | `task.created` | обновить экран задач |

| 14 | task → sync | async | `task.deleted` | синхронизация |
| 15 | клиент → pet | sync | `POST /api/v1/pets` | создать питомца |

## Сценарий сбоя (сага)

### Успешный путь

| Шаг | Кто | Что делает |
|---|---|---|
| 1 | клиент → family-service | `DELETE /api/v1/families/{familyId}/members/{memberId}` |
| 2 | family-service | проверяет права, ставит участнику статус PENDING_REMOVAL, пишет событие в outbox в той же транзакции |
| 3 | family-service → клиент | сразу отвечает 202 Accepted (результат клиент узнает позже через sync-service) |
| 4 | family-service → брокер | публикует `member.removal_started` |
| 5 | task-service | в одной локальной транзакции переназначает открытые задачи участника владельцу |
| 6 | task-service → брокер | публикует `tasks.reassigned` |
| 7 | family-service | получает `tasks.reassigned`, окончательно удаляет участника, публикует `member.removed` |
| 8 | sync-service, notification-service | по `member.removed` обновляют экраны семьи и уведомляют удалённого участника |

### Путь со сбоем

| Шаг | Кто | Что делает |
|---|---|---|
| 1 | клиент → family-service | `DELETE /api/v1/families/{familyId}/members/{memberId}` |
| 2 | family-service | проверяет права, ставит участнику статус PENDING_REMOVAL, пишет событие в outbox в той же транзакции |
| 3 | family-service → клиент | сразу отвечает 202 Accepted (результат клиент узнает позже через sync-service) |
| 4 | family-service → брокер | публикует `member.removal_started` |
| 5 | task-service | транзакция откатилась, задачи остались как были |
| 6 | task-service → брокер | публикует `tasks.reassign_failed` |
| 7 | family-service | **компенсация:** возвращает участнику статус ACTIVE, публикует `member.removal_failed` |
| 8 | notification-service | сообщает владельцу, что удаление не удалось |
| 9 | sync-service | убирает с экранов отметку «удаляется» |
